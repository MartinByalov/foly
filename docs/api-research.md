# Foly source review — 2026-11-03

This is the technical audit, deliberately separate from the presentation README.

## Admission gate for new providers

A successful HTTP response, JSON payload, GraphQL schema, manifest, or API directory entry is not user-visible functionality and is not sufficient for inclusion. A provider stays research-only unless Foly can turn its live response into an actual discovery that a user can see and use in the gallery.

Before enabling or counting a provider, verify all of the following:

- It returns a real visual discovery: an image or a meaningful data visualization, not only metadata, links, or an API explorer response.
- Images must decode and render in the Foly card; charts must render their verified data and labels. Reopening either discovery preserves its content and required credit.
- The card's user-facing source link opens a readable item page or browseable collection, not a raw API response, IIIF manifest, GraphiQL/schema page, or code-only endpoint. Keep machine endpoints for fetching and rights evidence separate from the link shown to users.
- Required attribution and rights are verified for the actual media or data, and the browser can fetch the API under the supported CORS behavior.
- The selected provider passes live checks and desktop and mobile browser samples. Failed or incomplete checks block inclusion; they are not counted as successes.

If a user has nothing concrete to see in Foly, do not add or count that API, even when its endpoint is technically reachable.

## Rights admission

- The API or catalog's own software license does not establish rights to its records or media. Validate the selected item's declared license and bind it to its human-facing source page, actual media URL, and evidence endpoint; a domain allowlist or JSON-LD value alone is not rights evidence.
- CC BY and CC BY-SA 2.0, 3.0, and 4.0 media may pass only with a recognized exact Creative Commons license URL and complete, consistent `author`, `source_url`, `license_url`, and `license_name` fields. The card displays the attribution and license; the in-memory archive preserves them for the current page session.
- CC BY-SA media is eligible only when retrieved directly from its provider and not persisted by Foly to a local cache or database. Discoveries and history remain in page memory and are not restorable from browser storage. Reassess this condition before adding any persistent cache or database.
- CC BY-ND is not auto-approved because Foly's display pipeline scales media; NC and unknown/restrictive rights remain rejected. A provider-wide policy can support item-level declarations, but cannot substitute for them.

## Implemented acceptance rules

1. Only a reviewed adapter with an explicit source policy may enter the production draw.
2. Independently check the rights of metadata and the exact image returned by the provider.
3. Accept CC0, Public Domain Mark and reviewed explicit public-domain declarations. Selected media may also use exact canonical CC BY 4.0 or CC BY-SA 4.0 URLs when the adapter supplies complete plain-text attribution, credit party, original title, original media link and the unchanged/scaled presentation note. Metadata remains independently reviewed under the original public-domain/CC0 gate; do not silently extend media permission to descriptive prose. Reject NC, ND, unknown, software-only and unreviewed versions/custom licences. These are implementation choices, not claims that other licences are unlawful.
4. Bind evidence to the exact item URL, image and thumbnail. Require HTTPS item/media/evidence URLs and a recent adapter check timestamp. This timestamp records when the adapter processed provider evidence, not a legal audit or a guarantee that an old dataset has been refreshed.
5. Reject before any image loading. Then apply existing metadata-safety checks and browser image decoding; retry another source on failure.
6. Preserve evidence in the discovery object and show source credits and a media-rights link on the card.

Provider statements cannot guarantee that an uploader owned all relevant rights. CC0 does not clear personality, privacy, publicity, trademark or every jurisdiction-specific issue. This implementation is evidence-based filtering, not legal clearance or image moderation.
